# Pa Tools packaging: what is done, what is open

The packaging scripts were renamed and rebranded on a Linux machine, with no macOS or Windows host.
Everything below the "Done" line was checked by reading and by syntax checks only, and should be tried once on
the real platform. Where the brand lives: `packaging/env.sh` (shell), the block at the top of
`packaging/windows/package.ps1`, and the table at the top of `rebrand.sh`; change it there, then run `./rebrand.sh`.

## Done on Linux

- `Info.plist.in` parses as a property list (all `@X@` placeholders substituted) and `entitlements.plist` and
  `patools.wxs` pass `xmllint`. Every `.sh` passes `bash -n`; every workflow, `nfpm.yaml` and both Flatpak
  manifests parse as YAML.
- The icon set, `Pa Tools.icns`, `patools.ico` and the hicolor PNGs were rendered from `assets/app-icon/icon.svg`.
- The DMG background, `background.tiff` and the Finder layout (`dmg-layout.DS_Store`) were regenerated by
  `packaging/macos/dmg/generate.py`, which runs on Linux.

## To do on a Mac

1. **Canonical `.icns`.** `Pa Tools.icns` was packed by `packaging/icons.py` (PNG entries; it loads the same). Make the
   Apple-built file once and commit it:
   ```sh
   iconutil -c icns "assets/app-icon/Pa Tools.iconset" -o "assets/app-icon/Pa Tools.icns"
   ```
2. **Check the DMG window.** Run `packaging/macos/package.sh`, open the DMG and check: volume name "Pa Tools", the
   window is 660 x 432, the background shows the Pa Tools artwork, and the "Pa Tools.app" and Applications icons sit on
   the two drop targets. The layout file holds an alias built without a Mac. If the icons are misplaced, edit the
   coordinates in `packaging/macos/dmg/generate.py` and run it again; see `packaging/macos/dmg/README.md`.
3. **Ad-hoc build and plugin test.** With no certificates `package.sh` signs ad-hoc. Then:
   ```sh
   codesign -d --entitlements - "Pa Tools.app"                 # both audio-input and disable-library-validation
   codesign -d --entitlements - pa-tools-cli                   # the CLI carries the same entitlements
   plutil -lint "Pa Tools.app/Contents/Info.plist"
   ```
   Launch the app and load a third-party VST3, CLAP and Audio Unit. They should load because of
   `com.apple.security.cs.disable-library-validation` (upstream gap G-05, `docs/gaps.md`). If one is refused, run
   `log stream --predicate 'process == "Pa Tools"'` while loading it and read the library-validation message.
4. **Intel and universal.** The default is a universal build (needs both rustup targets). `--arch x86_64` builds Intel
   only, `--arch aarch64` Apple silicon only; see `docs/releasing.md`.
5. **Developer ID and notarisation** need Gil's own certificate and Apple ID (secrets table in
   `docs/ci-notes-patools.md`). Upstream's certificate cannot be used.
